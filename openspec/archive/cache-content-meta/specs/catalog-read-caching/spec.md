# Spec Delta: catalog-read-caching

ต่อยอดจาก change `cache-catalog-reads` ซึ่งกำหนดกฎนี้ไว้แล้วสำหรับสินค้าและหมวดหมู่
delta นี้ขยายให้ครอบคลุมรายการเนื้อหา (`contents`)

## ADDED Requirements

### Requirement: รายการ meta ของเนื้อหาต้องแคชข้าม request
`getAllContentsMeta()` SHALL แคชผลลัพธ์ข้าม request ด้วย `unstable_cache` โดยใช้
cache key ของตัวเองที่ไม่ชนกับ key อื่นในระบบ (`products_all`, `categories_all`,
`products_data`, `company_info`) — ผู้เรียกทั้งสาม (หน้าแรกผ่าน `ProductsJsonLd`,
`/showcase/[id]`, `sitemap.xml`) SHALL ใช้ผลลัพธ์ก้อนเดียวร่วมกันแทนที่จะต่างคน
ต่างยิงคิวรี

#### Scenario: เปิดหน้าแรกและหน้าบทความต่อเนื่องกันโดยไม่มีการแก้เนื้อหา
- **WHEN** มีการเปิดหน้าแรกและหน้า `/showcase/[id]` หลายครั้งติดกัน โดยไม่มีการ
  สร้าง/แก้/ลบเนื้อหาคั่นกลาง
- **THEN** คิวรีอ่านตาราง `contents` ถูกยิงจริงเพียงครั้งเดียว ครั้งถัดไปเสิร์ฟจากแคช

### Requirement: ทุกเส้นทางที่เขียนตาราง `contents` ต้องล้างแคช
แคชของ `getAllContentsMeta()` SHALL ถูกล้างโดย **ทุก** เส้นทางที่เขียนตาราง
`contents` ไม่ใช่เฉพาะ route ที่อยู่ใต้ `app/api/contents/**` — ครอบคลุมทั้งการ
สร้าง แก้ไข ลบ การกู้คืนจาก revision และการลบแบบ cascade ตอน hard delete สินค้า

ชุดทดสอบ SHALL ตรวจข้อนี้จากไฟล์บนดิสก์จริง เพื่อให้เส้นทางเขียนที่เพิ่มเข้ามา
ภายหลังถูกจับได้โดยไม่ต้องแก้เทสต์

#### Scenario: แอดมินแก้เนื้อหาแล้วเปิดหน้าสาธารณะ
- **WHEN** แอดมินบันทึกการแก้ไขเนื้อหา แล้วเปิดหน้าที่แสดงรายการเนื้อหา
- **THEN** เห็นข้อมูลใหม่ทันทีในคำขอถัดไป ไม่ใช่ค่าที่แคชไว้ก่อนแก้

#### Scenario: กู้คืนเนื้อหาจาก revision
- **WHEN** แอดมินกู้คืนเนื้อหาผ่าน `PUT /api/revisions/[id]/restore`
- **THEN** แคชรายการเนื้อหาถูกล้าง และหน้าสาธารณะแสดงเวอร์ชันที่กู้คืนทันที

#### Scenario: hard delete สินค้าที่มีเนื้อหาผูกอยู่ (ความเสี่ยงหลักของ change นี้)
- **WHEN** แอดมิน hard delete สินค้าที่มีเนื้อหาผูกอยู่ ซึ่งทำให้เนื้อหานั้นถูกลบ
  จากฐานข้อมูลไปด้วย
- **THEN** แคชรายการเนื้อหาถูกล้างด้วย และ `sitemap.xml` SHALL ไม่ประกาศ URL
  `/showcase/{id}` ของเนื้อหาที่ถูกลบไปแล้ว — การประกาศ URL ที่ตอบ 404 ให้ Google
  คือ regression ของ bug ที่แก้ไปแล้วใน commit `5b0f220`

#### Scenario: เพิ่มเส้นทางเขียนใหม่โดยลืมล้างแคช
- **WHEN** มีโค้ดใหม่เรียก `addContent` / `updateContent` / `deleteContent` /
  `hardDeleteProduct` โดยไม่ได้เรียก `revalidateTag`
- **THEN** ชุดทดสอบล้มเหลว โดยระบุไฟล์ที่ขาดการล้างแคช

### Requirement: แคชรายการเนื้อหาต้องมีเพดานอายุ
แคชของ `getAllContentsMeta()` SHALL มีเพดานเวลา (`revalidate`) เพื่อให้การแก้ไข
ที่ไม่ผ่านเส้นทาง API (เช่น แก้ฐานข้อมูลโดยตรง) หรือกรณีที่การล้างแคชพลาดไป
กลายเป็นความค้างที่มีขอบเขตจำกัด ไม่ใช่ค้างตลอดไป

#### Scenario: เนื้อหาถูกแก้โดยไม่ผ่าน API
- **WHEN** ข้อมูลในตาราง `contents` ถูกแก้โดยตรงจากเครื่องมือภายนอก
- **THEN** ข้อมูลใหม่ปรากฏภายในเพดานเวลาที่กำหนด ไม่ค้างค่าเดิมตลอดไป
