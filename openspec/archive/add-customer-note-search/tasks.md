## 2. Phase 2 — ตรรกะการค้นหาและแทนที่ (บริสุทธิ์ ทดสอบได้)
- [x] 2.1 `app/lib/noteSearch.ts` — ไม่มี DOM ไม่มี DB ไม่มี fetch
- [x] 2.2 `buildMatcher({ term, matchCase, useRegex })` คืน matcher หรือเหตุผล
      ที่ปฏิเสธเป็นภาษาไทย
- [x] 2.3 **ปฏิเสธ pattern ที่จับคู่ข้อความว่างได้** (`.*`, `a?`, `(?:)`) —
      ทดสอบด้วยการรัน pattern กับ `""` ไม่ใช่การเดาจากตัวอักษรใน pattern
- [x] 2.4 ปฏิเสธคำค้นว่าง, pattern ผิดไวยากรณ์, pattern ยาวเกินเพดาน
- [x] 2.5 `findMatches(note, matcher)` คืนจำนวนครั้ง + ตำแหน่ง + ข้อความรอบๆ
      (ตัดมาจากบันทึกจริง เป็นข้อความล้วน)
- [x] 2.6 `applyReplace(note, matcher, replacement)` — ต้องไม่แตะตัวขึ้นบรรทัด
- [x] 2.7 กัน catastrophic backtracking: จำกัดความยาว pattern และความยาวบันทึก
      ที่ยอมรับต่อครั้ง
- [x] 2.8 เทสต์ `__tests__/lib/noteSearch.test.ts` — ไทยล้วน, ไทยปนอังกฤษ,
      ตรง/ไม่ตรงตัวพิมพ์, regex ที่ดีและที่ต้องปฏิเสธ, เจอหลายครั้งในบันทึกเดียว,
      แทนที่ด้วยค่าว่าง, บันทึกที่มีอักขระคล้ายแท็ก HTML, บันทึกหลายบรรทัด

## 3. Phase 3 — Store + API
- [x] 3.1 `app/lib/customerNoteSearchStore.ts` — `searchNotes` และ
      `replaceInNotes`
- [x] 3.2 `searchNotes` อ่านเฉพาะที่ต้องใช้ (id, ชื่อ, บริษัท, note) และมีเพดาน
      จำนวนแถว **เมื่อชนเพดานต้องบอกว่าเหลืออีกกี่ราย ห้ามตัดเงียบ**
- [x] 3.3 `replaceInNotes` อยู่ใน `withTransaction` เดียว — สำเร็จหมดหรือไม่มีเลย
- [x] 3.4 callback ต้อง idempotent — mint UUID ภายใน และคำนวณจากค่าที่อ่านใน
      ความพยายามนั้น (`withTransaction` retry ได้ถึง 3 ครั้ง)
- [x] 3.5 ปฏิเสธรายราย: บันทึกใหม่ยาวเกิน 2000, ค่าปัจจุบันไม่ตรงกับที่หน้าจอเห็น
- [x] 3.6 `saveRevision("customer", …)` ทุกรายก่อนเขียน โดยใช้ connection ของ
      transaction เดียวกัน
- [x] 3.7 `app/api/customers/note-search/route.ts` (GET) และ
      `app/api/customers/note-replace/route.ts` (POST)
- [x] 3.8 ทุก route เป็น `withRoute("<fallback ไทย>", handler)` +
      `await requireAuth()` และทุกค่าผ่าน `sanitizePlainText`
- [x] 3.9 เทสต์ store + route — รวมการยิงคำขอเองโดยไม่ผ่านหน้าจอ (คำค้นว่าง,
      เกินเพดาน, pattern อันตราย) ต้องไม่มี UPDATE ถูกส่ง
