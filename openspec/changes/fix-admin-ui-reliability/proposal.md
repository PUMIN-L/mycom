# Proposal: แก้บั๊กเล็กๆ ที่กระทบการใช้งานฟอร์ม/หน้าแอดมิน

> ที่มา: adversarial review ทั้งโปรเจกต์ (2026-08-31), มิติ reliability-ux

## Why
สองบั๊กสุดท้ายที่เหลือจากการรีวิว — ไม่ได้ทำลายข้อมูล แต่ทำให้แอดมินเข้าใจผิด
สถานะระบบ หรือกรอกฟอร์มไม่ได้เลยจากบั๊กเล็กๆ ที่หาสาเหตุยาก

## What Changes

1. **CRM alert center โชว์ "ไม่มีแจ้งเตือน 🎉" ตอน fetch ล้มเหลว** —
   `app/crm/alerts/page.tsx:52-63` เช็คแค่ `if (res.ok)` แล้วค่อย set state —
   ถ้า response ไม่ ok (เช่น session หมดอายุได้ 401, หรือ 500) จะไม่มีการ toast
   error ใดๆ เลย ปล่อยให้ `alerts` เป็น `null` ซึ่ง render ออกมาเป็น empty state
   ที่บอกว่า "ทุกอย่างอัปเดตเรียบร้อยแล้ว" — แอดมินจะเข้าใจผิดว่าไม่มีอะไรต้อง
   ติดตามทั้งที่จริงๆ ระบบแค่โหลดข้อมูลไม่สำเร็จ (pattern เดียวกันนี้อยู่ใน
   `app/customers/page.tsx:104-106` และ `EquipmentTab.tsx:219-224` ด้วย)

2. **Regex ลบตัวอักษรที่ไม่ใช่ตัวเลขของเบอร์โทรพนักงานขายผิด** —
   `app/customers/page.tsx:1023` ใช้ `e.target.value.replace(/\\D/g, "")` —
   backslash คู่ทำให้ regex กลายเป็น "ตัวอักษร D ที่มี backslash นำหน้า" (ไม่มีทาง
   match กับเบอร์โทรได้เลย) แทนที่จะเป็น `/\D/g` (ตัวอักษรที่ไม่ใช่เลข) ที่ใช้ถูก
   ในฟอร์มบริษัท/ลูกค้าข้างเคียง (บรรทัด 876, 925) ผลคือถ้าพิมพ์/วางเบอร์โทรที่มี
   ขีดหรือช่องว่าง ฟิลด์จะไม่ผ่าน `pattern="[0-9]*"` และปุ่มบันทึกกดไม่ได้เลย

## Impact
- Affected code: `app/crm/alerts/page.tsx`, `app/customers/page.tsx`
  (+ พิจารณา `EquipmentTab.tsx` ด้วยถ้าจะแก้ pattern เดียวกันให้ครบ)
- Affected specs: `admin-ui-reliability` (ใหม่)
- งานเล็ก ทำเร็ว เหมาะเก็บเป็นกลุ่มสุดท้าย
