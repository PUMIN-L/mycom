# Spec Delta: purchase-order

## ADDED Requirements

### Requirement: สร้างใบสั่งซื้อได้พร้อมเลขที่เอกสารอัตโนมัติ ไม่ซ้ำกับเอกสารประเภทอื่น
Admin ที่ login แล้ว SHALL สร้างใบสั่งซื้อ (PO) ใหม่ได้จากหน้า
`/purchase-order` เลขที่เอกสาร SHALL ถูกมินต์อัตโนมัติในรูปแบบ
`PO<DDMMYY>-<ลำดับ>` (เช่น `PO150926-01`) โดยใช้ **ตัวจ่ายเลขและ ledger
เดียวกับที่ใบเสนอราคา/ใบแจ้งหนี้ใช้อยู่แล้ว** (`used_docnos`,
`nextDocNo`/`docNoPrefixes` ใน `quotationNumber.ts`) — SHALL ไม่มีการสร้าง
กลไกจ่ายเลขใหม่แยกต่างหาก และเลขที่ PO SHALL ไม่มีวันชนกับเลขที่ของเอกสาร
ประเภทอื่นเพราะใช้ ledger กลางร่วมกัน

หากมีการบันทึกพร้อมกัน (สอง client มินต์เลขเดียวกันในวันเดียวกัน) ระบบ SHALL
ตรวจจับด้วย unique constraint ของ `used_docnos.docNo` แล้วคืน HTTP 409 ให้
client เลื่อนไปเลขถัดไปเอง — SHALL ไม่ silently เขียนทับหรือสร้างเลขซ้ำ

#### Scenario: สร้าง PO ใบแรกของวัน
- **WHEN** admin สร้าง PO ในวันที่ยังไม่มีใครออก PO เลย
- **THEN** เลขที่เริ่มจากลำดับตั้งต้นของวันนั้น (ตามกติกาเดียวกับใบเสนอราคา)

#### Scenario: สองแท็บมินต์เลขชนกัน
- **WHEN** สอง client บันทึก PO เลขเดียวกันพร้อมกัน (race condition)
- **THEN** client ที่บันทึกไม่ทันได้รับ HTTP 409 และเลื่อนไปเลขถัดไปให้เอง
  ไม่มี PO สองใบเลขซ้ำกันในระบบ

#### Scenario: Guest เรียก route ของ PO
- **WHEN** ไม่มี session ที่ login เรียก `GET/POST /api/purchase-orders` หรือ
  route ย่อยใดๆ ของมัน
- **THEN** ระบบตอบ 401 ไม่คืนข้อมูล PO ใดๆ และไม่สร้าง/แก้ไขอะไร

### Requirement: PO ที่บันทึกแล้วแก้ไขในแถวเดิมไม่ได้ ต้องยกเลิกแล้วออกใบใหม่แทน
PO เป็นคำสั่งซื้อที่ผูกพันกับซัพพลายเออร์แล้ว จึงใช้กติกาความเข้มงวดแบบ
เอกสารทางบัญชี (`billing_documents`) ไม่ใช่แบบใบเสนอราคา: เมื่อบันทึกครั้ง
แรกแล้ว ระบบ SHALL **ไม่มีทางแก้ไขเนื้อหา (`data`) ของแถวเดิมได้อีก** ไม่ว่า
ผ่าน UI หรือ API ใดๆ

การแก้ไขที่ต้องการทำได้ทางเดียวคือ:
1. **ยกเลิก** (`POST /api/purchase-orders/[id]/cancel`) — ตั้ง `cancelledAt`
   เท่านั้น SHALL ไม่ DELETE แถวทิ้ง (เอกสารที่อาจพิมพ์ส่งซัพพลายเออร์ไปแล้ว
   ต้องมีหลักฐานเหลือเสมอ)
2. **ออกใบใหม่แทน** (`POST /api/purchase-orders/[id]/supersede`) — สร้างแถว
   ใหม่ **เลขที่ใหม่ทั้งใบ** (ไม่ใช่แค่ suffix เวอร์ชันต่อท้ายเลขเดิมแบบใบ
   เสนอราคา) พร้อมตั้ง `supersededById` ของแถวเก่าให้ชี้มาที่แถวใหม่ ในทราน
   แซกชันเดียวกัน

แถวที่ถูก cancel ไปแล้วหรือ supersede ไปแล้ว SHALL ปฏิเสธการ cancel/supersede
ซ้ำอีกครั้ง (กันการสร้างโซ่ที่สับสนหรือ overwrite `supersededById` ที่ตั้งไว้
แล้ว)

#### Scenario: พยายามแก้ไข PO ที่บันทึกแล้วตรงๆ
- **WHEN** มีความพยายามเรียก endpoint หรือฟังก์ชันใดๆ ที่จะเขียนทับ `data`
  ของ PO ที่มีอยู่แล้วในแถวเดิม
- **THEN** ไม่มี endpoint/ฟังก์ชันเช่นนั้นอยู่ในระบบเลย (ตรวจสอบด้วยเทสต์ที่
  ยืนยันว่า `poStore.ts` ไม่มีฟังก์ชันแก้ `data` ของแถวที่มีอยู่แล้วตรงๆ)

#### Scenario: ยกเลิก PO
- **WHEN** admin กด "ยกเลิกใบนี้" บน PO ที่ยังไม่เคยถูกยกเลิกหรือแทนที่มาก่อน
- **THEN** แถวนั้นถูกตั้ง `cancelledAt` เป็นเวลาปัจจุบัน ยังอยู่ในระบบครบถ้วน
  และหน้าดูเอกสาร (`?id=...&view=1`) แสดงป้าย "ยกเลิกแล้ว" ชัดเจน

#### Scenario: ออกใบใหม่แทนใบเดิม
- **WHEN** admin กด "ออกใบใหม่แทนใบนี้" บน PO ที่ยังไม่เคยถูก supersede มา
  ก่อน แก้ไขข้อมูลบางส่วนแล้วบันทึก
- **THEN** ระบบสร้าง PO ใบใหม่เลขที่ใหม่ทั้งใบ พร้อมตั้ง `supersededById`
  ของใบเก่าให้ชี้มาที่ใบใหม่ ใบเก่ายังอยู่ครบถ้วนในระบบ (ไม่ถูกลบหรือแก้)

#### Scenario: พยายามยกเลิกหรือออกใบใหม่แทน PO ที่ถูกจัดการไปแล้ว
- **WHEN** admin กด "ยกเลิก" บน PO ที่ `cancelledAt` ถูกตั้งไว้แล้ว หรือกด
  "ออกใบใหม่แทน" บน PO ที่ `supersededById` ถูกตั้งไว้แล้ว
- **THEN** ระบบปฏิเสธการทำซ้ำ พร้อมข้อความอธิบายว่าใบนี้ถูกจัดการไปแล้ว

### Requirement: หน้าตาเอกสารต้องครบตามแบบฟอร์มใบสั่งซื้อมาตรฐานที่ใช้กันในไทย
เอกสาร PO ที่แสดงบนหน้าจอและไฟล์ PDF ที่ดาวน์โหลด SHALL มีองค์ประกอบครบตาม
แบบฟอร์มมาตรฐาน:
- หัวกระดาษ: โลโก้ + ชื่อ/ที่อยู่/เลขผู้เสียภาษี **ของบริษัทผู้ซื้อ (เรา)**
  คู่กับของ **ผู้ขาย/ซัพพลายเออร์**
- เลขที่ใบสั่งซื้อ, วันที่ออกเอกสาร, วันที่ต้องการรับสินค้า
- ตารางรายการ: ลำดับ / รายละเอียดสินค้า-บริการ / จำนวน / หน่วย / ราคาต่อหน่วย
  / จำนวนเงิน
- ส่วนลด (ถ้ามี), ยอดรวมก่อนภาษี, ภาษีมูลค่าเพิ่ม 7%, ยอดรวมสุทธิ พร้อม
  ตัวหนังสือไทยกำกับจำนวนเงิน
- เงื่อนไขการชำระเงิน, เงื่อนไขการส่งมอบ, หมายเหตุ
- ช่องลงนาม 3 ช่อง: ผู้สั่งซื้อ, ผู้อนุมัติ, ผู้ขาย (ผู้รับคำสั่งซื้อ)

PDF ที่ดาวน์โหลด SHALL สร้างฝั่ง client (html2canvas + jsPDF บนกระดาษ A4)
เหมือนใบเสนอราคา — SHALL ไม่เพิ่มการพึ่งพา PDF library ฝั่ง server ใดๆ

#### Scenario: ดูตัวอย่างเอกสารก่อนบันทึก
- **WHEN** admin กรอกข้อมูล PO ในฟอร์ม
- **THEN** พรีวิวกระดาษ A4 ฝั่งขวาอัปเดตทันทีให้ตรงกับสิ่งที่กรอก รวมยอดรวม/
  VAT/ยอดสุทธิที่คำนวณสด

#### Scenario: ดาวน์โหลด PDF
- **WHEN** admin กด "ดาวน์โหลด PDF" บน PO ที่บันทึกแล้ว
- **THEN** ได้ไฟล์ PDF ขนาด A4 ที่มีองค์ประกอบครบตามรายการข้างต้น แบ่งหน้า
  ถูกต้องถ้ารายการยาวเกินหนึ่งหน้า

### Requirement: ดาวน์โหลดใบสั่งซื้อเป็นไฟล์ Excel แบบฟอร์มจำลอง PDF ได้
นอกจาก PDF แล้ว admin SHALL ดาวน์โหลด PO ที่บันทึกแล้วเป็นไฟล์ `.xlsx` ได้
ด้วย โดย SHALL เป็น 1 ชีทที่จัดวางให้หน้าตาใกล้เคียงเอกสาร PDF จริง (ไม่ใช่
ตาราง label–value 2 ชีทแบบ flat) ใช้ตัวช่วยกลางที่ใช้ร่วมกับเอกสารประเภทอื่น
(`buildDocumentFormSheet()`/`downloadDocumentFormExcel()` ใน
`app/lib/documentFormExcel.ts`, สร้างสไตล์ผ่าน `xlsx-js-style`) ไฟล์ที่ได้
SHALL มีองค์ประกอบครบตามลำดับนี้ในชีทเดียว:
- หัวเรื่องเอกสาร ("ใบสั่งซื้อ / PURCHASE ORDER") อยู่กลางแถวบนสุด
- ข้อมูลผู้ซื้อ (เรา) และผู้ขาย/ซัพพลายเออร์ (ชื่อ/ที่อยู่/เบอร์โทร/เลขผู้เสีย
  ภาษี) เรียงต่อกัน
- เลขที่ PO, วันที่ออกเอกสาร, วันที่ต้องการรับสินค้า
- ตารางรายการสินค้า/บริการที่มีเส้นขอบและหัวตารางพื้นสีเข้ม (ลำดับ, รายการ,
  จำนวน, หน่วย, ราคาต่อหน่วย, จำนวนเงิน) ตรงกับที่แสดงในเอกสาร PDF/หน้าจอทุก
  แถว
- สรุปยอด (ยอดก่อนภาษี/VAT 7%/ยอดรวมสุทธิ) ชิดขวา แถวยอดรวมสุทธิ SHALL หนา
  และมีเส้นคั่นด้านบนเพื่อเน้น
- เงื่อนไขการชำระเงิน/การส่งมอบ
- แถวลงลายเซ็นสามช่อง (ผู้สั่งซื้อ/ผู้อนุมัติ/ผู้ขาย)

ค่าที่เขียนลงทุกเซลล์ SHALL ผ่านการป้องกัน Excel formula injection ตามกลไก
เดิม (`sanitizeExcelCell` จาก `xlsxExport.ts`) เหมือน export อื่นๆ ในระบบ —
SHALL ไม่มี export ใดใน PO ที่ข้ามการป้องกันนี้ ไฟล์ `.xlsx` ที่ได้ไม่ใช่ PDF
โดยตัวมันเอง — admin เปิดไฟล์แล้วใช้ฟังก์ชัน Save as PDF / Print → Save as
PDF ของโปรแกรม Excel/Numbers เองเพื่อได้ไฟล์ PDF จากชีทนี้อีกต่อหนึ่ง

#### Scenario: ดาวน์โหลด Excel ของ PO ที่มีรายการหลายแถว
- **WHEN** admin กด "ดาวน์โหลด Excel" บน PO ที่บันทึกแล้ว ซึ่งมีหลายรายการ
  สินค้า
- **THEN** ได้ไฟล์ `.xlsx` ที่มี 1 ชีทตามโครงร่างข้างต้น ตารางรายการมีจำนวน
  แถวเท่ากับจำนวนรายการในเอกสารเป๊ะ และยอดสรุปตรงกับที่คำนวณในหน้าจอ/PDF

#### Scenario: รายการมีอักขระที่ Excel ตีความเป็นสูตร
- **WHEN** ชื่อรายการสินค้าหรือหมายเหตุขึ้นต้นด้วยอักขระอย่าง `=`, `+`, `-`,
  `@`
- **THEN** ค่าที่เขียนลง Excel ถูก escape ไม่ให้ Excel ตีความเป็นสูตรหรือ
  DDE trigger เมื่อเปิดไฟล์ (ผ่าน `sanitizeExcelCell` เดิม)

### Requirement: ข้อมูลซัพพลายเออร์/บริษัทบน PO เป็นสำเนาที่แก้ไขได้อิสระ ไม่ join สดจากตารางซัพพลายเออร์
เมื่อ admin เลือกซัพพลายเออร์ผ่าน dropdown ตอนสร้าง PO ระบบ SHALL เติมชื่อ/
ที่อยู่/เลขผู้เสียภาษี/ผู้ติดต่อ/เบอร์โทรจากตาราง `suppliers` ให้อัตโนมัติ
ลงในฟอร์ม — ค่าที่เติมนี้ SHALL แก้ไขได้อิสระก่อนบันทึก และ **เมื่อบันทึกแล้ว
ค่าที่บันทึกไว้ในเอกสาร SHALL ไม่เปลี่ยนตามข้อมูลซัพพลายเออร์ที่ถูกแก้ไขทีหลัง
อีกเลย** (เอกสารเก็บเป็นสำเนา ไม่ join สดทุกครั้งที่เปิดดู) — วิธีเดียวกับที่
ใบเสนอราคาเก็บชื่อ/ที่อยู่/เบอร์โทรลูกค้าเป็นข้อความอิสระในตัวเอกสาร

#### Scenario: แก้ไขข้อมูลซัพพลายเออร์หลังออก PO ไปแล้ว
- **WHEN** admin แก้ไขที่อยู่ของซัพพลายเออร์ในหน้าจัดการซัพพลายเออร์ หลังจาก
  เคยออก PO ที่อ้างถึงซัพพลายเออร์รายนั้นไปแล้ว
- **THEN** PO เก่าที่เปิดดูยังแสดงที่อยู่แบบเดิมตอนที่ออกใบ ไม่เปลี่ยนตาม
  ข้อมูลซัพพลายเออร์ปัจจุบัน

### Requirement: ยอดเงินคำนวณถูกต้องตามลำดับส่วนลด → VAT 7% → ยอดสุทธิ พร้อมปัดเศษสตางค์
การคำนวณยอดเงินของ PO SHALL เป็นไปตามลำดับ: ส่วนลดต่อรายการก่อน (ไม่เกิน
จำนวนเงินหรือ 100% ของแต่ละรายการ) → รวมยอด → หักส่วนลดรวมทั้งใบ (ถ้ามี) →
คิด VAT 7% บนยอดที่เหลือ → ยอดรวมสุทธิ ทุกขั้นตอน SHALL ปัดเศษสตางค์ (2
ตำแหน่งทศนิยม) แบบเดียวกับที่ใบเสนอราคาใช้ (`round2()`)

#### Scenario: PO ไม่มีส่วนลด
- **WHEN** สร้าง PO ที่ไม่มีส่วนลดใดๆ
- **THEN** ยอดรวมสุทธิ = ผลรวมรายการทั้งหมด + VAT 7% ของยอดนั้น ตรงเป๊ะ

#### Scenario: PO มีทั้งส่วนลดต่อรายการและส่วนลดรวมทั้งใบ
- **WHEN** สร้าง PO ที่มีทั้งส่วนลดต่อรายการบางแถว และส่วนลดรวมท้ายใบ
- **THEN** ยอดที่คิด VAT คือยอดหลังหักส่วนลดทั้งสองชั้นแล้ว ไม่ใช่ยอดก่อนหัก
  ส่วนลดใดๆ

### Requirement: ตารางซัพพลายเออร์รองรับที่อยู่และเลขผู้เสียภาษี
ตาราง `suppliers` SHALL มีคอลัมน์ `address` และ `taxId` (nullable, เพิ่มแบบ
non-breaking กับข้อมูลเดิม) เพื่อให้เลือกซัพพลายเออร์ตอนออก PO แล้วเติมข้อมูล
พิมพ์บนเอกสารได้ครบโดยไม่ต้องพิมพ์ใหม่ทุกครั้ง หน้าจัดการซัพพลายเออร์ที่มีอยู่
แล้ว (`/suppliers`) SHALL มีช่องกรอกสองฟิลด์นี้เพิ่มในฟอร์มเพิ่ม/แก้ไข

#### Scenario: ซัพพลายเออร์เดิมที่ยังไม่เคยกรอกที่อยู่/เลขผู้เสียภาษี
- **WHEN** admin เปิดดูซัพพลายเออร์ที่สร้างไว้ก่อนงานนี้ (ไม่มีค่าในสองฟิลด์
  ใหม่)
- **THEN** หน้าจอไม่พัง แสดงช่องว่างให้กรอกเพิ่มได้ตามปกติ ไม่ถือเป็นข้อมูล
  เสีย
