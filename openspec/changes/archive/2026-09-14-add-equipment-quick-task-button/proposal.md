# Proposal: ปุ่มสร้างสิ่งที่ต้องทำ ผูกกับอุปกรณ์โดยตรง จากหน้ารายละเอียดอุปกรณ์

## Why

เหมือนกับที่ทำไปแล้วกับหน้ารายละเอียดลูกค้า (`add-customer-quick-task-button`)
— หน้ารายละเอียดอุปกรณ์ (`EquipmentDetailsModal`, เปิดจากแท็บ "อุปกรณ์ที่ขาย"
ในหน้า `/customers`) ไม่มีทางสร้างงานในกระดาน "สิ่งที่ต้องทำ" ที่ผูกกับเครื่อง
ที่กำลังดูอยู่ได้เลย ต้องออกไปที่ `/crm/alerts` แล้วค้นหาเครื่องคนเดิมซ้ำใน
ตัวเลือกผูกลิงก์ของฟอร์ม (`TASK_LINK_TARGETS` มี `"equipment"` อยู่แล้ว)

กลไกทุกอย่างมีอยู่แล้วเหมือนกรณีลูกค้า ไม่ต้องสร้างระบบใหม่ แค่เพิ่มทางลัด
อีกจุดหนึ่ง

## What Changes

### 1. ปุ่มใหม่ใน `EquipmentDetailsModal`

- เพิ่มปุ่ม "📝 สร้างสิ่งที่ต้องทำ" ในหัวข้อของ modal (แถวเดียวกับปุ่ม
  "✏️ แก้ไข" ที่มีอยู่แล้ว) กดแล้วเปิด `TaskFormModal` พร้อม `initialLinks`
  ผูกกับอุปกรณ์เครื่องนี้ทันที — label คำนวณด้วย `buildTaskLinkLabel("equipment",
  { productName: equipment.productName, serialNumber: equipment.serialNumber })`
  ตัวเดียวกับที่ตัวเลือกลิงก์ในฟอร์มใช้อยู่แล้ว (เหมือนกรณีลูกค้าทุกประการ)
- โหลดหัวข้องานแบบ lazy, หัวข้อยังต้องเลือกเองเสมอ, ลิงก์ที่ seed มายังลบออก
  ได้ก่อนบันทึก — กติกาเดียวกับปุ่มฝั่งลูกค้าทุกข้อ
- **ข้อความแจ้งผล ใช้ `alert(...)` ไม่ใช่ toast** — `EquipmentDetailsModal`
  ไม่มีระบบ toast อยู่แล้ว (ทุกจุดของ modal นี้ใช้ `alert()` แจ้งผลอยู่แล้ว
  เช่น บันทึกนัดหมาย/ลบนัดหมาย/OTP) เพิ่มปุ่มนี้แล้วใช้ toast จะกลายเป็น
  รูปแบบที่สองภายใน modal เดียวกัน จึงทำตามของเดิมเพื่อความสม่ำเสมอ

### 2. `EquipmentDetailsModal` เป็น component ที่ใช้ร่วมกัน 2 ที่ — ปุ่มนี้จึงขึ้นทั้งคู่

`EquipmentDetailsModal` ถูกเปิดจาก **สองที่**:
  - แท็บ "อุปกรณ์ที่ขาย" ในหน้า `/customers` (ที่ขอมา)
  - การ์ดแจ้งเตือนที่ผูกเครื่องบน `/crm/alerts` (กด "แก้ไข" บนการ์ด
    "กำหนดการ"/"ประกันใกล้หมด"/"สอบเทียบ"/"ข้อมูลไม่ครบ" จะเปิด modal
    เดียวกันนี้)

เพิ่มปุ่มไว้ **ใน component ที่ใช้ร่วมกัน** (ไม่ใช่คัดลอกไปสองที่) ปุ่มนี้จึง
**ขึ้นทั้งสองที่โดยอัตโนมัติ** — เสนอว่านี่คือพฤติกรรมที่ถูกต้อง (สอดคล้อง กัน
ทั้งสองทางเข้า ไม่ต้องเขียนซ้ำ) แต่เป็นจุดที่อยากให้ยืนยันก่อน เพราะขอบเขตที่
พิมพ์มาคือ "หน้าอุปกรณ์ที่ขาย" เท่านั้น — ถ้าไม่ต้องการให้ขึ้นตอนเปิดจาก
`/crm/alerts` ด้วย ต้องเพิ่ม prop แยกเพื่อปิดปุ่มเฉพาะทางเข้านั้น (งานเพิ่ม
เล็กน้อย)

### 3. รวบตัวโหลด "หัวข้องาน" ให้เป็นตัวเดียวกันทั้งแอป (แก้ของเดิมที่เพิ่งทำให้ลูกค้าไปด้วย)

ตอนทำปุ่มฝั่งลูกค้า ตัวโหลดหัวข้องานถูก cache ไว้ที่ **state ของหน้า
`/customers` เท่านั้น** (อายุแค่ตอนอยู่หน้านั้น) ตอนนี้จะมีจุดที่สองที่ต้องใช้
หัวข้องานเหมือนกัน (`EquipmentDetailsModal` ซึ่งเปิดได้จากสองหน้า) ถ้าคัดลอก
logic โหลด+cache แบบเดิมไปอีกจุด จะเป็นโค้ดซ้ำชุดที่สาม (ตัวแรกคือหน้า
ลูกค้า) และมีความเสี่ยงว่าจะลืมอัปเดตพร้อมกันในอนาคต (แบบเดียวกับที่เจอปัญหา
มาหลายรอบในเซสชันนี้)

จึงเสนอ **ดึงตัวโหลดหัวข้องานออกมาเป็น hook ใช้ร่วมกันตัวเดียว**
(`useTaskTopics`) โดยเลียนแบบ `useTaskLinkTargets` ที่มีอยู่แล้วใน
`TaskLinkChips.tsx` (cache ระดับ **module ทั้งแอป** ไม่ใช่ระดับหน้า — โหลด
ครั้งเดียวทั้ง session ไม่ว่าจะเปิดจากหน้าไหนก่อน) แล้ว **ย้ายปุ่มฝั่งลูกค้าที่
ทำไปแล้วมาใช้ hook ตัวนี้ด้วย** (แทนที่ state เดิมของหน้า `/customers`) — ผล
ลัพธ์ที่แอดมินเห็นเหมือนเดิมทุกประการ (โหลดครั้งแรกที่กดปุ่ม, ครั้งถัดไปไม่โหลด
ซ้ำ) เพียงแต่ตอนนี้ "ครั้งถัดไป" หมายถึงทั้ง session ไม่ใช่แค่หน้าเดิม —
เปิด `/customers` กดปุ่มโหลดหัวข้อไปแล้ว พอไปเปิดอุปกรณ์ที่ `/crm/alerts`
แล้วกดปุ่มนี้ ก็ไม่ต้องโหลดซ้ำอีกรอบ

## Impact

- Affected specs:
  - `crm-task-board` — เพิ่ม requirement ใหม่ (ปุ่มฝั่งอุปกรณ์) และ MODIFIED
    requirement เดิม 1 ข้อ (ฝั่งลูกค้า) แค่ปรับคำอธิบายขอบเขตการ cache หัวข้อ
    จาก "ตลอดอายุของหน้า" เป็น "ตลอด session" — พฤติกรรมที่แอดมินเห็นไม่เปลี่ยน
    เพียงแค่ครอบคลุมกว้างขึ้น
- Affected code:
  - `app/components/useTaskTopics.ts` (**ใหม่**) — hook ใช้ร่วมกัน, cache
    ระดับ module, มี `__resetTaskTopics()` เป็น test seam (แบบเดียวกับ
    `__resetTaskLinkTargets`)
  - `app/components/modals/EquipmentDetailsModal.tsx` — ปุ่มใหม่ + ใช้ hook
    ด้านบน + เปิด `TaskFormModal`
  - `app/customers/page.tsx` — **รื้อ** state โหลด/cache หัวข้องานที่เขียนไว้
    เอง (`taskTopics`, `isLoadingTaskTopics` และ logic ใน
    `handleOpenTaskForm`) ให้เรียก `useTaskTopics` แทน ปุ่มและพฤติกรรมที่เห็น
    ไม่เปลี่ยน
  - `__tests__/components/EquipmentDetailsModal.test.tsx` (ใหม่ ถ้ายังไม่มี
    ไฟล์นี้) — ปุ่มเปิดฟอร์มพร้อมลิงก์เครื่องนี้, ลบลิงก์ที่ seed มาได้,
    หัวข้อโหลดไม่สำเร็จ/ไม่มีหัวข้อ → ไม่เปิดฟอร์ม
  - `__tests__/components/TaskFormModal.test.tsx` — ไม่แก้ (ทดสอบ
    `initialLinks` ไว้ครบแล้วจากงานลูกค้า ใช้ร่วมกันได้)
  - `__tests__/pages/customersQuickTaskButton.test.tsx` — ปรับให้ reset
    module-level cache ของ `useTaskTopics` ใน `beforeEach` (ของเดิม reset
    แค่ state ของหน้า ซึ่งจะหายไปหลัง refactor)
- ไม่กระทบ:
  - `app/lib/db.ts`, `SCHEMA_VERSION`, `task_links` schema — ไม่มีของใหม่
  - `TASK_LINK_TARGETS`, `addTask`/`updateTask`, ทุก route ใต้
    `/api/admin/tasks*` — ไม่แก้แม้แต่บรรทัดเดียว
  - พฤติกรรมปุ่มฝั่งลูกค้าที่แอดมินเห็น — เหมือนเดิมทุกประการ มีแค่ขอบเขตแคช
    ที่กว้างขึ้น (ดีขึ้น ไม่ใช่ผลข้างเคียงที่เห็นได้)
  - ทุกจุดอื่นของ `EquipmentDetailsModal` (นัดหมาย, OTP ลบนัด, ใบ Job) —
    ไม่แตะ
