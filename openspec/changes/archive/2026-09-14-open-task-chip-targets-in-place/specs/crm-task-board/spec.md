# Spec Delta: crm-task-board

## MODIFIED Requirements

### Requirement: ชิปลิงก์ต้องพาไปยังปลายทางได้จริง และปลายทางที่ถูกลบต้องขึ้น "ถูกลบแล้ว" โดยไม่พังและไม่ 404
ชิปแต่ละอันบนการ์ดงาน SHALL พาไปยังปลายทางของมันได้ในคลิกเดียว:
- `quotation` → นำทางไป `/quotation?id=<quotations.id>&view=1` (เปิดแบบอ่าน
  อย่างเดียว)
- `document` → นำทางไป `/document/<documents.id>`
- `customer` → SHALL เปิด `CustomerDetailsModal` **ในหน้าเดิม** (ไม่นำทางออก
  จาก `/crm/alerts`, ไม่เปลี่ยน URL) — component และกลไกดึงข้อมูลเดียวกันกับ
  ที่ปุ่ม "แก้ไข" บนการ์ดนัดโทรลูกค้าใช้อยู่แล้ว (`open-customer-profile-
  in-place`)
- `equipment` → SHALL เปิด `EquipmentDetailsModal` **ในหน้าเดิม** เช่นกัน —
  component เดียวกับที่การ์ด "กำหนดการ" ที่ผูกเครื่องใช้อยู่แล้ว

`customer`/`equipment` SHALL ใช้ฟังก์ชันโหลด-แล้ว-เปิด modal ตัวเดียวกันกับที่
ปุ่ม "แก้ไข" ของการ์ดแจ้งเตือนใช้ — SHALL ไม่มีโค้ด fetch+เปิด modal ชุดที่สอง
สำหรับชิปโดยเฉพาะ เมื่อโฮสต์ที่ render ชิป (`TaskBoardSection`) ไม่ได้รับ
ฟังก์ชันเปิด modal มา (ไม่มี caller ส่งมาให้) ชิปทั้งสองประเภท SHALL ตกกลับไป
นำทางด้วย `<Link href>` แบบเดิม แทนที่จะเป็นปุ่มที่กดแล้วไม่มีอะไรเกิดขึ้น

เนื่องจากปัจจุบัน `app/customers/page.tsx` **ไม่รับ URL parameter ใดเลย** —
ทั้งแท็บที่เปิดอยู่ (`activeTab`) และลูกค้า/เครื่องที่กำลังดูรายละเอียด เป็น
state ภายในคอมโพเนนต์ล้วนๆ — หน้านั้น SHALL ยังคงรับพารามิเตอร์เพื่อ
deep-link ไปยังแท็บและลูกค้า/เครื่องที่ระบุได้เหมือนเดิม (สำหรับผู้ที่เข้าหน้า
`/customers` ตรงๆ) และพารามิเตอร์ที่ชี้ไปยังของที่ไม่มีอยู่แล้ว SHALL ไม่ทำให้
หน้าพัง — การเปลี่ยนแปลงนี้ไม่แตะกลไก deep-link ของหน้านั้นเลย เพียงแค่กระดาน
งานเลือกเปิด modal ในที่เดิมแทนการนำทางไปที่นั่น

ก่อนแสดงผล ระบบ SHALL ตรวจว่าปลายทางแต่ละอัน **ยังมีอยู่จริงหรือไม่** (คิวรี่
เป็นชุดเดียวต่อประเภท ไม่ยิงทีละชิป) ชิปที่หาปลายทางไม่เจอ SHALL แสดง label
snapshot พร้อมป้าย **"ถูกลบแล้ว"** ในสไตล์ที่ดูไม่กดได้ (disabled) และ
**SHALL ไม่นำทางหรือเปิด modal ใดๆ เลย** — งานนั้น SHALL ยังใช้งานได้ครบ
(กดสำเร็จ/แก้ไข/ลบลิงก์ที่ตายแล้วออกได้) และระบบ SHALL **ไม่ลบแถว
`task_links` ที่ตายแล้วให้อัตโนมัติ** เพราะ label ที่ค้างไว้คือหลักฐานเดียวที่
บอกว่างานนี้เคยอ้างถึงอะไร

#### Scenario: กดชิปใบเสนอราคาที่ยังอยู่
- **WHEN** admin กดชิปใบเสนอราคาบนการ์ดงาน
- **THEN** เปิด `/quotation?id=<id>&view=1` และเห็นใบนั้นแบบอ่านอย่างเดียว

#### Scenario: กดชิปเอกสารที่ยังอยู่
- **WHEN** admin กดชิปเอกสาร
- **THEN** เปิด `/document/<id>` ของเอกสารนั้น

#### Scenario: ใบเสนอราคาถูก purge ไปแล้วตาม retention 2 ปี
- **WHEN** งานถูกสร้างไว้เมื่อ 2 ปีก่อนพร้อมลิงก์ใบเสนอราคา แล้ว cron ลบใบ
  เสนอราคานั้นทิ้งตาม retention
- **THEN** งานยังอยู่บนกระดานครบ ชิปนั้นแสดง label เดิม (เช่น
  "QT-2568-001") ต่อท้ายด้วย "ถูกลบแล้ว" กดไม่ได้ ไม่นำทางไปไหน และไม่มี
  request ไปยัง `/quotation?id=...` ที่จะได้หน้าเปล่า

#### Scenario: deep-link ไปยังลูกค้าที่ยังอยู่
- **WHEN** admin กดชิปลูกค้าบนการ์ดงาน ขณะอยู่ที่ `/crm/alerts`
- **THEN** `CustomerDetailsModal` ของลูกค้ารายนั้นเปิดขึ้นทับหน้าเดิม — URL
  ยังเป็น `/crm/alerts` ไม่เปลี่ยนไปเป็น `/customers` ปิด modal แล้วต้องเห็น
  กระดานงานเดิมทันที

#### Scenario: กดชิปเครื่องจักรที่ยังอยู่ — เปิดในหน้าเดิม ไม่นำทางออก
- **WHEN** admin กดชิปเครื่องจักรบนการ์ดงาน
- **THEN** `EquipmentDetailsModal` ของเครื่องนั้นเปิดขึ้นทับหน้าเดิมเช่นกัน
  ไม่นำทางออกจาก `/crm/alerts`

#### Scenario: ลูกค้าหรือเครื่องจักรถูกลบไปแล้ว
- **WHEN** ปลายทางประเภท `customer` หรือ `equipment` ไม่มีแถวอยู่แล้ว
- **THEN** ชิปแสดง snapshot + "ถูกลบแล้ว" แบบกดไม่ได้เช่นเดียวกัน (ไม่เปิด
  modal เปล่า ไม่มี request ไปหาข้อมูลที่ไม่มีอยู่) และงานยังกดปิดเป็นสำเร็จ
  ได้ตามปกติ

#### Scenario: งานที่ทุกลิงก์ตายหมดแล้ว
- **WHEN** ปลายทางทั้งหมดของงานหนึ่งถูกลบไปหมด
- **THEN** การ์ดงานยังแสดงหัวข้อ ชื่องาน รายละเอียด และวันครบกำหนดตามปกติ
  โดยมีชิป "ถูกลบแล้ว" เรียงอยู่ — ไม่มี error และไม่มีการซ่อนงานทิ้ง
