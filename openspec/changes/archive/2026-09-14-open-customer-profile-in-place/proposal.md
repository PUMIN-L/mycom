# Proposal: กด "แก้ไข" บนนัดโทรลูกค้าแล้วยังอยู่หน้า /crm/alerts เดิม

## Why

`route-customer-call-edit-to-profile` (ที่เพิ่ง deploy ไป) เปลี่ยนปุ่ม "แก้ไข"
บนการ์ด "นัดโทรลูกค้า" ให้เปิดข้อมูลลูกค้าแทนฟอร์มแก้นัด — ถูกต้องตามที่ขอ
แต่ทำด้วยวิธี **นำทางออกจากหน้า** (`router.push("/customers?customerId=...")`)
ซึ่งพาแอดมินออกจากศูนย์แจ้งเตือน CRM ไปเลย เจ้าของระบบทดสอบจริงแล้วอยากให้
**ยังอยู่ที่ `/crm/alerts` เหมือนเดิม** ไม่เปลี่ยนหน้า

ปัญหาคือ "ข้อมูลลูกค้า" ที่ต้องแสดง (แผนก/อีเมล/เบอร์โทร/บันทึกลูกค้า +
ปุ่ม "สร้างสิ่งที่ต้องทำ" ที่เพิ่งเพิ่ม + ส่วนนัดโทรลูกค้า) **ทั้งหมดเขียนอยู่
ในหน้า `/customers` เท่านั้น** ฝังเป็นส่วนหนึ่งของไฟล์นั้นโดยตรง (ไม่ใช่
component แยก) การจะแสดงข้อมูลชุดเดียวกันนี้ที่ `/crm/alerts` โดยไม่นำทางออก
มีสองทางเลือก:

- **(ก) คัดลอก JSX ทั้งชุดไปแปะอีกที่ในหน้า `/crm/alerts`** — เร็วแต่ทำให้เกิด
  โค้ดซ้ำสองชุดที่ต้องแก้พร้อมกันตลอดไป (บั๊ก/ฟีเจอร์ใหม่ของ "ดูข้อมูลลูกค้า"
  ต้องจำแก้ 2 ที่ ซึ่งเป็นรูปแบบปัญหาที่เจอมาหลายรอบแล้วในโปรเจกต์นี้)
- **(ข) ดึงส่วนแสดงข้อมูลลูกค้าออกมาเป็น component ใช้ร่วมกัน** เหมือนที่
  `EquipmentDetailsModal` ทำอยู่แล้ว (component เดียว ใช้ได้ทั้งจากแท็บ
  "อุปกรณ์ที่ขาย" และจากการ์ดแจ้งเตือนที่ผูกเครื่อง) — เขียนครั้งเดียว ใช้ได้
  ทั้งสองหน้า แก้ที่เดียวจบ

**เสนอ (ข)** ตามรูปแบบที่โปรเจกต์นี้ใช้อยู่แล้วสำหรับกรณีเดียวกันเป๊ะ

## What Changes

### 1. ดึง "Viewing Customer Modal" ออกมาเป็น `CustomerDetailsModal` (component ใหม่)

ย้าย JSX + state ทั้งหมดของ modal ดูข้อมูลลูกค้าที่ฝังอยู่ใน
`app/customers/page.tsx` วันนี้ ไปเป็น
`app/components/modals/CustomerDetailsModal.tsx` (คู่กับ
`EquipmentDetailsModal.tsx` ที่มีอยู่แล้ว) — รวมทุกอย่างที่เคยอยู่ในหน้า:

- แสดงแผนก / อีเมล / เบอร์โทรศัพท์
- "บันทึกลูกค้า" พร้อมแก้ไขในตัว (inline edit) — บันทึกผ่าน
  `PUT /api/customers/[id]` เหมือนเดิมทุกประการ
- ส่วนนัดโทรลูกค้า (`CustomerCallScheduleSection`)
- ปุ่ม "📝 สร้างสิ่งที่ต้องทำ" ที่เพิ่งเพิ่ม (`add-customer-quick-task-button`)
  — ย้ายเข้าไปอยู่ใน component นี้เลย ใช้ `useTaskTopics` cache ตัวเดิม
  พฤติกรรมไม่เปลี่ยน

`app/customers/page.tsx` เปลี่ยนมาเรียก `<CustomerDetailsModal customer={...}
onClose={...} onSaved={...} />` แทน — **หน้าตาและพฤติกรรมที่แอดมินเห็นบน
`/customers` เหมือนเดิมทุกประการ** งานนี้คือการย้ายโค้ด ไม่ใช่เปลี่ยน UI

### 2. `/crm/alerts` เรียก component เดียวกันนี้ แทนการนำทางออก

- `resolveAlertEditRoute` **ไม่แก้** — ยังคืน `{ kind: "customer_profile",
  customerId }` เหมือนเดิม (ฟังก์ชันนี้แค่บอกว่า "ต้องใช้ข้อมูลลูกค้าคนนี้"
  ไม่ได้ตัดสินว่าจะแสดงยังไง)
- `handleEditClick` ในหน้า `/crm/alerts` เปลี่ยนจาก `router.push(...)` เป็น:
  ดึงข้อมูลลูกค้าเต็มด้วย `GET /api/customers/[id]` (route ใหม่ — ดูข้อ 3)
  แล้วเปิด `CustomerDetailsModal` **ในหน้าเดิม** ปิดแผงรายละเอียดแจ้งเตือน
  (`selectedAlert`) เหมือนที่ทำตอนเปิดโมดัลอุปกรณ์
- โหลดไม่สำเร็จ (ลูกค้าถูกลบไปแล้ว ฯลฯ) → แจ้งเตือนภาษาไทย ไม่เปิด modal
  เปล่า ไม่นำทางไปไหน — ตามแบบเดียวกับที่ปุ่ม "แก้ไข" บนการ์ดที่ผูกเครื่อง
  ทำอยู่แล้วเมื่อโหลดข้อมูลอุปกรณ์ไม่สำเร็จ
- URL ของ `/crm/alerts` **ไม่เปลี่ยน** ไม่มีการเติม query param ใดๆ (เหมือน
  ตอนเปิดรายละเอียดอุปกรณ์จากหน้านี้ ซึ่งก็ไม่แตะ URL เช่นกัน)

### 3. `GET /api/customers/[id]` (route ใหม่)

วันนี้มีแต่ `GET /api/customers` (ดึงทั้งลิสต์) — หน้า `/customers` หาลูกค้า
คนเดียวจากลิสต์ที่โหลดมาแล้วทั้งหมด (ใช้ได้เพราะหน้านั้นโหลดทุกคนอยู่แล้ว)
แต่ `/crm/alerts` ไม่มีลิสต์ลูกค้าอยู่ในมือ และ **ไม่ควรโหลดลูกค้าทั้งหมด
(กำลังจะมีประมาณ 6,000 คน) แค่เพื่อหาคนเดียว** จึงต้องมี endpoint ดึงทีละคน
โดยตรง — คิวรี่เดียวกับที่ list ใช้ (join ชื่อบริษัท) เปลี่ยนแค่เพิ่ม
`WHERE customers.id = ?`

## Impact

- Affected specs:
  - `crm-alert-surface` — MODIFIED requirement เดิม (ที่ `route-customer-
    call-edit-to-profile` เพิ่งแก้) เปลี่ยนจาก "นำทางไป /customers" เป็น
    "เปิด modal ในหน้าเดิม"
- Affected code:
  - `app/components/modals/CustomerDetailsModal.tsx` (**ใหม่**) — ย้ายทุก
    อย่างจาก Viewing Customer Modal เดิมมาไว้ที่นี่ รวมปุ่มสร้างงานที่เพิ่ง
    เพิ่ม
  - `app/customers/page.tsx` — ลบ JSX/state ของ modal เดิม เรียก component
    ใหม่แทน (ลบโค้ด ~150+ บรรทัด, พฤติกรรมเดิมทุกประการ)
  - `app/crm/alerts/page.tsx` — `handleEditClick`: `customer_profile` เปลี่ยน
    จาก `router.push` เป็น fetch + เปิด `CustomerDetailsModal` ในหน้าเดิม
  - `app/api/customers/[id]/route.ts` — เพิ่ม `GET` (มี `PUT`/`DELETE` อยู่
    แล้ว)
  - เทสต์: ย้าย/เพิ่มเทสต์ของ modal ให้ตรง component ใหม่, เทสต์หน้า
    `/crm/alerts` ที่ยืนยันว่า URL ไม่เปลี่ยนและ modal เปิดในหน้าเดิม, เทสต์
    route ใหม่ (`GET /api/customers/[id]`)
- ไม่กระทบ:
  - `resolveAlertEditRoute` (`app/lib/alertEditRoute.ts`) — ไม่แก้เลย
  - การ์ด "กำหนดการ" ที่ผูกเครื่อง และปุ่มสร้างงานฝั่งอุปกรณ์ — ไม่แตะ
  - `PUT /api/customers/[id]`, `DELETE /api/customers/[id]` — ของเดิมไม่แก้
  - `app/lib/db.ts`, `SCHEMA_VERSION` — ไม่มีคอลัมน์/ตารางใหม่
