# Spec Delta: crm-task-board

## MODIFIED Requirements

### Requirement: กระดานงานต้องแยกให้เห็นชัดจากการแจ้งเตือนอัตโนมัติบนหน้าเดียวกัน
กระดานงาน SHALL อยู่บนหน้าของตัวเอง (`/crm/tasks`) แยกออกจากการ์ดแจ้งเตือน
อัตโนมัติของ `getAlerts()` บน `/crm/alerts` โดยสิ้นเชิง เพราะมันคือโน้ตที่
admin เขียนเตือนตัวเอง ไม่ใช่สิ่งที่ระบบตรวจพบ (D2) โดยเฉพาะ:
- กระดานงาน SHALL **ไม่ปรากฏอยู่ในหน้า** `/crm/alerts` เลย ไม่ว่าจะเป็นแท็บ
  หนึ่งใน `tabOptions` (ซึ่งเป็นชุดแท็บของ "สิ่งที่ระบบตรวจพบเอง" ล้วนๆ) หรือ
  บล็อกแยกท้ายหน้าแบบเดิม — `/crm/alerts` SHALL มีเพียงปุ่ม/การ์ดลิงก์ไปยัง
  `/crm/tasks` แทน (ดู requirement ใหม่ใน `crm-alert-surface`)
- `/crm/alerts` SHALL **ไม่ยิง request** ไปยัง `/api/admin/tasks` หรือ
  `/api/admin/task-topics` อีกต่อไป — ข้อมูลกระดานงานถูกโหลดที่ `/crm/tasks`
  เท่านั้น
- ในหน้า `/crm/tasks` การ์ดงานที่บันทึกเอง SHALL แสดงเป็นเนื้อหาหลักของหน้า
  ไม่ต้องแยกจากอะไรอีก (ไม่มีการ์ดแจ้งเตือนอัตโนมัติบนหน้านี้ให้ปนกัน)
- การ์ดงานทุกใบ SHALL มีป้ายกำกับที่อ่านออกทันทีว่า **"บันทึกเอง"** (คงไว้
  แม้ย้ายหน้า เพื่อไม่ให้สับสนกับแจ้งเตือนอัตโนมัติที่เคยอยู่ข้างๆ กัน)
- ข้อความบนการ์ดงาน SHALL ไม่ใช้ถ้อยคำที่ทำให้เข้าใจว่าระบบตรวจพบเอง (เช่น
  "ประกันใกล้หมด" / "ข้อมูลไม่ครบ") — ข้อความบนการ์ดคือสิ่งที่ admin พิมพ์เอง
- กระดานงาน SHALL ไม่มีปุ่ม "เลื่อนการแจ้งเตือน" (snooze) ของระบบเตือนอัตโนมัติ
  และ SHALL ไม่เขียนแถวใดลง `alert_snoozes`
- ชิปลิงก์ลูกค้า/เครื่องบนการ์ดงาน (`open-task-chip-targets-in-place`) SHALL
  ยังคงเปิด `CustomerDetailsModal`/`EquipmentDetailsModal` **ในหน้า
  `/crm/tasks` เอง** (ไม่นำทางออกจาก `/crm/tasks`, ไม่เปลี่ยนไป `/crm/alerts`
  หรือ `/customers`) — ใช้ฟังก์ชันโหลด-แล้ว-เปิด modal ตัวเดียวกันกับที่
  `/crm/alerts` ใช้สำหรับปุ่ม "แก้ไข" ของมันเอง (hook กลาง
  `useCustomerEquipmentDetails`) ไม่ใช่โค้ด fetch+เปิด modal ชุดที่สอง

#### Scenario: เปิด `/crm/tasks`
- **WHEN** admin เปิด `/crm/tasks`
- **THEN** เห็นกระดานงานทั้งหมด พร้อมป้าย "บันทึกเอง" บนทุกการ์ด และไม่มี
  การ์ดแจ้งเตือนอัตโนมัติปนอยู่บนหน้านี้เลย

#### Scenario: เปิดแท็บ "ทั้งหมด"
- **WHEN** admin เปิด `/crm/alerts` ที่แท็บ "ทั้งหมด"
- **THEN** เห็นเฉพาะการ์ดแจ้งเตือนอัตโนมัติเท่านั้น — ไม่มีการ์ดงานที่บันทึก
  เองปนอยู่บนหน้านี้อีกต่อไป (ย้ายไปอยู่ที่ `/crm/tasks` ทั้งหมดแล้ว) มีเพียง
  ปุ่ม/การ์ดลิงก์ไปหน้า "สิ่งที่ต้องทำ" และหน้านี้ไม่มี network request ไปยัง
  `/api/admin/tasks` หรือ `/api/admin/task-topics`

#### Scenario: อ่านการ์ดงานแล้วต้องรู้ว่าใครเป็นคนสร้าง
- **WHEN** มีคนเปิดดูการ์ดงาน "โทรตามลูกค้าเรื่องเครื่องชั่ง" บน `/crm/tasks`
- **THEN** เห็นป้าย "บันทึกเอง" บนการ์ด และไม่มีข้อความใดที่สื่อว่าระบบตรวจพบ
  เงื่อนไขอะไรให้

#### Scenario: การแจ้งเตือนอัตโนมัติยังทำงานเหมือนเดิม
- **WHEN** กระดานงานถูกย้ายออกจาก `/crm/alerts` ไปเป็นหน้าของตัวเอง
- **THEN** แท็บเดิมทั้งหมดของ `/crm/alerts` (ทั้งหมด / กำหนดการ / นัดโทร
  ลูกค้า / ประกันใกล้หมด / ใกล้ถึงกำหนดสอบเทียบ / ข้อมูลไม่ครบ / เอกสารค้าง /
  ลูกหนี้ค้างชำระ) และปุ่ม snooze ของการ์ดเดิมยังทำงานเหมือนเดิมทุกประการ

#### Scenario: สลับแท็บแจ้งเตือนแล้วกระดานงานต้องยังหาเจอ
- **WHEN** admin สลับจากแท็บ "ทั้งหมด" ไปแท็บ "เอกสารค้าง" บน `/crm/alerts`
- **THEN** ปุ่ม/การ์ดลิงก์ไปหน้า "สิ่งที่ต้องทำ" (ท้ายฟีด และในหัวหน้า) ยังอยู่
  ในตำแหน่งเดิมเสมอ ไม่ถูกตัวกรองของแท็บแจ้งเตือนกรองหายไป — ไม่ว่าแท็บไหน
  ก็ยังกดไปหน้า `/crm/tasks` ได้เหมือนกันทุกครั้ง

#### Scenario: กดชิปลูกค้า/เครื่องบนการ์ดงานในหน้าใหม่
- **WHEN** admin กดชิปลูกค้าหรือเครื่องบนการ์ดงาน ขณะอยู่ที่ `/crm/tasks`
- **THEN** `CustomerDetailsModal`/`EquipmentDetailsModal` ของรายการนั้นเปิด
  ขึ้นทับหน้าเดิม — URL ยังเป็น `/crm/tasks` ไม่เปลี่ยนไปที่อื่น
