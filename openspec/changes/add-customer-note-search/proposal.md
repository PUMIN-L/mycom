# Proposal: ค้นหาและแทนที่คำในบันทึกลูกค้าทุกคน แบบ Search ของ VS Code

## Why

`บันทึกลูกค้า` คือ **สมุดบันทึกการโทรที่สะสมมาเป็นปีๆ** ของลูกค้าแต่ละราย
หน้าตาจริงเป็นแบบนี้

```
6/9/26  โทรหา QC ส่งข้อมูล Company ไปให้ทางอีเมล์เรียบร้อย
7/9/26  โทรหา เพื่อติดตามใบเสนอราคา ลูกค้าสนใจให้ทำใบเสนอราคา
10/9/26 โทรหาเพื่อติดตามใบเสนอราคา เวอร์เนีย ลูกค้ายังไม่มีอัปเดต
```

**ปัญหาคือมันค้นข้ามคนไม่ได้เลย** ช่องค้นหาในหน้ารายชื่อลูกค้าวันนี้
(`app/customers/page.tsx`) ค้นได้แค่ **ชื่อลูกค้า** กับ **ชื่อบริษัท** เท่านั้น
คำที่อยู่ใน `note` ไม่เคยถูกค้น

ผลที่ตามมา 3 อย่าง

**1. คำถามที่ตอบไม่ได้ ทั้งที่คำตอบอยู่ในระบบแล้ว**
"ใครบ้างที่เคยคุยเรื่องเวอร์เนีย" / "รายไหนที่ค้างใบเสนอราคาอยู่" — ข้อมูลอยู่ครบ
แต่ต้องเปิดดูทีละคน 7 คนยังพอไหว ร้อยคนคือเปิดไม่ไหว

**2. พิมพ์ผิดซ้ำๆ แก้ไม่ได้**
ชื่อรุ่น ชื่อแบรนด์ หรือชื่อคนที่พิมพ์ผิดแบบเดิมกระจายอยู่ในบันทึกของหลายราย
วันนี้ต้องไล่แก้ทีละคน ซึ่งแปลว่าไม่มีใครแก้

**3. ไม่มีทางย้อนกลับถ้าแก้ผิด — และนี่คือเรื่องที่ต้องแก้ก่อน**
`revisions` เก็บประวัติก่อนแก้ไว้ให้ `product` / `content` / `document`
(`app/lib/revisionStore.ts:7`) แต่ **ไม่มี `customer`** การแก้บันทึกลูกค้าวันนี้
จึงเป็นการเขียนทับที่กู้คืนไม่ได้เลย จะเพิ่มการค้นหา-แทนที่ทีละหลายคนลงบนของที่
ไม่มีปุ่มถอยหลัง ไม่ได้

## What Changes

### ค้นหา

- ช่องค้นหาใหม่ในหน้ารายชื่อลูกค้า ที่ค้นใน `customers.note` ของ **ทุกคน**
  แยกจากช่องค้นชื่อ/บริษัทเดิม ซึ่งไม่ถูกแตะ
- ตัวเลือกแบบ VS Code:
  - **`Aa` ตรงตามตัวพิมพ์ใหญ่-เล็ก** — ทำ
  - **`.*` Regular Expression** — ทำ แต่ปิดไว้เป็นค่าเริ่มต้น และมีด่านกันไว้
    (ดู "จุดที่อันตราย")
  - **`ab` ทั้งคำ — ไม่ทำ และนี่คือการตัดสินใจ ไม่ใช่การลืม** `\b` ของ
    JavaScript นิยามบน `[A-Za-z0-9_]` เท่านั้น ภาษาไทยไม่มีช่องว่างระหว่างคำ
    ดังนั้น `\bเวอร์เนีย\b` จะ **ไม่เจออะไรเลยตลอดกาล** — ปุ่มที่กดแล้วผลลัพธ์
    ว่างเปล่าเสมอ แย่กว่าปุ่มที่ไม่มี

### ผลลัพธ์เป็นตาราง

คอลัมน์: ชื่อลูกค้า · บริษัท · **จำนวนที่เจอ** · **ข้อความรอบๆ คำที่เจอ พร้อม
ไฮไลต์** · ปุ่มเปิดดูลูกค้ารายนั้น

ข้อความรอบๆ สำคัญที่สุดในตารางนี้ — เห็นคำอย่างเดียวไม่พอ ต้องเห็นว่ามันอยู่ใน
ประโยคแบบไหน ถึงจะรู้ว่าใช่คำที่ตั้งใจหาหรือเปล่าก่อนจะกดแทนที่

### แทนที่

- ช่อง "แทนที่ด้วย" + **แทนที่รายคน** และ **แทนที่ทั้งหมด**
- **ตัวอย่างก่อนเขียนเสมอ** — เห็นของเดิม → ของใหม่ รายคน ไม่ใช่เห็นแค่จำนวน
- เขียนทั้งหมดใน `withTransaction` เดียว สำเร็จทั้งชุดหรือไม่มีใครถูกแก้เลย
- **เก็บประวัติก่อนเขียนทุกครั้ง** ผ่าน `saveRevision("customer", …)`

### ไม่ต้องแก้โครงสร้างฐานข้อมูล

`revisions.entityType` เป็น `VARCHAR(32)` แบบทั่วไปอยู่แล้ว (`app/lib/db.ts`)
การเพิ่ม `"customer"` จึงเป็นการขยาย type ใน TypeScript เท่านั้น
**`SCHEMA_VERSION` ไม่ต้องขยับ** และต้องไม่ขยับ

## จุดที่อันตราย และตั้งใจกันไว้อย่างไร

**1. ไม่มีปุ่มถอยหลัง → ต้องสร้างก่อน**
งานแรกของ change นี้ไม่ใช่ช่องค้นหา แต่คือทำให้การแก้บันทึกลูกค้า **ทุกทาง**
เก็บประวัติไว้ก่อนเขียน รวมถึงการกดแก้ไขทีละคนที่มีอยู่เดิมด้วย

**2. Regex คือปืนที่ลั่นใส่เท้าตัวเองได้**
คนใช้ระบบนี้เป็นเจ้าของกิจการ ไม่ใช่โปรแกรมเมอร์ พิมพ์ `.*` แล้วกดแทนที่ทั้งหมด
= ล้างบันทึกของทุกคนทิ้งในคลิกเดียว จึงต้อง **ปฏิเสธ pattern ที่จับคู่กับ
ข้อความว่างได้** ปฏิเสธคำค้นที่ว่าง และบังคับผ่านหน้าตัวอย่างเสมอ

**3. บันทึกถูกตัดที่ 2000 ตัวอักษรแบบเงียบๆ**
`app/api/customers/route.ts:43` และ `[id]/route.ts:27` ทำ
`sanitizePlainText(...).substring(0, 2000)` — ถ้าคำใหม่ยาวกว่าคำเดิม บันทึกอาจ
ทะลุ 2000 แล้ว **ท้ายบันทึกหายไปโดยไม่มีใครรู้** ต้องตรวจรายคนก่อนเขียน แล้ว
**ปฏิเสธรายนั้นพร้อมบอกเหตุผล ไม่ใช่ตัดทิ้ง**

**4. คนสองคนแก้พร้อมกัน**
ระหว่างที่ดูตัวอย่างอยู่ อาจมีคนแก้บันทึกคนเดียวกันไปแล้ว การเขียนทับจะกลืน
งานเขา ต้องส่งค่าที่หน้าจอเห็นตอนนั้นไปด้วย แล้วปฏิเสธถ้าไม่ตรง — วิธีเดียวกับ
ที่ `add-alert-date-search` ใช้กันการเลื่อนวันซ้ำ

**5. ขึ้นบรรทัดใหม่ต้องไม่พัง**
บันทึกแสดงผลแบบ `whitespace-pre-wrap` โครงบรรทัดคือสิ่งที่ทำให้อ่านออกว่า
แต่ละวันคุยอะไร การแทนที่ต้องไม่ยุ่งกับตัวขึ้นบรรทัด

## ที่ไม่ทำ และเหตุผล

- **ไม่ค้นในช่องอื่น** — ค้นเฉพาะ `note` ตามที่สั่ง ชื่อ/บริษัท/แผนก/เบอร์โทร
  มีช่องค้นเดิมอยู่แล้ว
- **ไม่แตะช่องค้นหาเดิม** ที่ค้นชื่อและบริษัท
- **ไม่ทำ "ทั้งคำ"** ด้วยเหตุผลด้านบน
- **ไม่ลบบันทึกทิ้งทั้งอัน** เครื่องมือนี้แทนที่คำ ไม่ใช่เครื่องมือลบข้อมูล
