# Proposal: ปุ่มสร้างสิ่งที่ต้องทำ ผูกกับลูกค้าโดยตรง จากหน้ารายละเอียดลูกค้า

## Why

หน้ารายละเอียดลูกค้า ("Viewing Customer Modal" ที่เปิดจากหน้า `/customers`)
ไม่มีทางสร้างงานในกระดาน "สิ่งที่ต้องทำ" ที่ผูกกับลูกค้าคนที่กำลังดูอยู่ได้เลย
วันนี้ถ้าอยากสร้างงานแบบนี้ต้องออกไปที่ `/crm/alerts` กด "สร้างงานใหม่" แล้ว
**ค้นหาลูกค้าคนเดิมซ้ำอีกครั้ง** ในตัวเลือกผูกลิงก์ของฟอร์ม — ทั้งที่กำลังเปิด
โปรไฟล์ของคนนั้นอยู่ตรงหน้าพอดี เสียเวลาและเสี่ยงเลือกผิดคนถ้าชื่อซ้ำกัน (ซึ่ง
เกิดขึ้นจริง — ลูกค้าหลายรายชื่อ "คุณสมชาย" ต่างบริษัทกัน)

ข่าวดีคือ **กลไกการผูกงานกับลูกค้ามีอยู่แล้วเต็มรูปแบบ**:
`task_links` (คีย์หลัก `(taskId, targetType, targetId)`) รองรับ
`targetType: "customer"` อยู่แล้ว, `addTask` รับ `links[]` ตอนสร้างได้ตรงๆ,
และมีฟังก์ชันคำนวณ label เดียวกันทั้งฝั่งเซิร์ฟเวอร์ (`buildLinkLabel` ใน
`taskStore.ts`) กับฝั่ง client (`buildTaskLinkLabel` ใน `TaskLinkChips.tsx`
— import เข้า client component ได้ตรง ไม่ต้องเขียน label ซ้ำเป็นครั้งที่สาม)
งานนี้จึงไม่ใช่การสร้างระบบผูกลิงก์ใหม่ **แค่เพิ่มทางลัด**: ปุ่มบนหน้าลูกค้าที่
เปิด `TaskFormModal` เดิม มาพร้อมลิงก์ลูกค้าคนนี้ผูกไว้ให้แล้วตั้งแต่เปิดฟอร์ม
ไม่ต้องไปเลือกเองอีกที

## What Changes

- **`app/components/TaskFormModal.tsx`** — เพิ่ม prop ใหม่ที่เป็น optional:
  `initialLinks` ใช้ pre-seed ลิงก์ **เฉพาะตอนสร้างงานใหม่เท่านั้น**
  (`task` ที่ส่งเข้ามาเป็น `null`/`undefined`) โหมดแก้ไขงานเดิมยังอ่านลิงก์จาก
  `task.links` เหมือนเดิมทุกประการ ไม่ถูก `initialLinks` แทรกแซง ลิงก์ที่ preset
  มายังคง**ลบออกได้ตามปกติก่อนกดบันทึก** ผ่านปุ่ม "ลบ" ที่มีอยู่แล้วในชิปทุกอัน
  — ไม่ล็อกไว้ ในกรณีที่แอดมินเปิดฟอร์มจากหน้าลูกค้าผิดคนแล้วอยากถอด/แก้

- **`app/customers/page.tsx`** — เพิ่มปุ่ม "📝 สร้างสิ่งที่ต้องทำ" ใน Viewing
  Customer Modal กดแล้วเปิด `TaskFormModal` (โหมดสร้างใหม่) พร้อม
  `initialLinks` = ลิงก์ประเภท `"customer"` ไปยัง `viewingCustomer.id` และ
  label ที่คำนวณด้วย `buildTaskLinkLabel("customer", { name, companyName })`
  ตัวเดียวกับที่ตัวเลือกลิงก์ในฟอร์มใช้อยู่แล้วตอนแอดมินค้นหาลูกค้าเอง
  - หัวข้องาน (topic) **ยังต้องเลือกเองตามปกติ ไม่เดาให้** — API บังคับว่า
    ต้องมีหัวข้อที่ยังเปิดใช้งานอยู่เสมอ (`POST /api/admin/tasks` ตอบ 400
    ถ้าไม่มี) การเดาหัวข้อผิดจะแย่กว่าไม่เดาเลย
  - รายการหัวข้อ (`GET /api/admin/task-topics`) โหลดแบบ **lazy** — ครั้งแรก
    ที่กดปุ่มนี้เท่านั้น แล้ว cache ไว้ในหน้า ไม่ใช่โหลดทุกครั้งที่เปิดหน้า
    `/customers` เพราะแอดมินส่วนใหญ่ที่เปิดดูลูกค้าจะไม่ได้ใช้ปุ่มนี้ทุกครั้ง
  - บันทึกสำเร็จ: ปิดฟอร์ม + toast "สร้างงานสำเร็จ — ผูกกับลูกค้ารายนี้แล้ว" +
    **อยู่หน้าเดิม** (ไม่เด้งไป `/crm/alerts`) เพราะแอดมินกำลังตั้งใจดูข้อมูล
    ลูกค้าอยู่ ไม่ได้ตั้งใจจะออกจากหน้านี้

- **ไม่แตะ**: `task_links` schema, `TASK_LINK_TARGETS`, `addTask` /
  `updateTask`, ทุก route ใต้ `/api/admin/tasks*`, กระดานงานที่ `/crm/alerts`
  (งานที่สร้างจากทางลัดนี้ขึ้นบนกระดานเหมือนงานทั่วไปทุกประการ เพราะเป็นแถว
  เดียวกันในตาราง `crm_tasks`/`task_links` เดียวกัน ไม่มีตารางแยก)

### ยังไม่ได้ตัดสินใจ — เสนอค่าเริ่มต้นไว้ ถ้าตอบว่า "ตามนี้" จะใช้เลย

1. **ตำแหน่งปุ่มใน modal** — เสนอ: แถวเดียวกับปุ่มปิด (X) มุมบนขวา เพราะตอนนี้
   modal ยังไม่มีแถบปุ่ม action ด้านล่างเลย (จบด้วยส่วนนัดโทรลูกค้าเป็นบล็อก
   สุดท้าย)
2. **หลังบันทึกสำเร็จ** — เสนอ: toast แล้วอยู่หน้าเดิม พร้อมลิงก์
   "ดูในกระดานงาน" ในตัว toast ให้กดไปดูได้ถ้าต้องการ ไม่บังคับเด้งไป
3. **หัวข้องานเริ่มต้น** — เสนอ: ไม่เดา ให้แอดมินเลือกเองทุกครั้ง เหมือนตอนกด
   "สร้างงานใหม่" จากกระดานตอนไม่ได้กรองหัวข้อใดไว้อยู่ก่อน

## Impact

- Affected specs:
  - `crm-task-board` (เพิ่ม requirement ใหม่ — ไม่แก้ requirement เดิม)
- Affected code:
  - `app/components/TaskFormModal.tsx` — prop `initialLinks` ใหม่
  - `app/customers/page.tsx` — ปุ่มใหม่ + state เปิด/ปิดฟอร์ม + โหลดหัวข้อแบบ
    lazy + toast
  - `__tests__/components/TaskFormModal.test.tsx` — เคสใหม่: `initialLinks`
    seed เฉพาะตอนสร้าง ไม่ทับ `task.links` ตอนแก้ไข, และยังลบออกได้ก่อนบันทึก
  - เทสต์หน้า `/customers` ใหม่ — ยืนยันว่ากดปุ่มแล้วฟอร์มเปิดมาพร้อมลิงก์ของ
    ลูกค้าคนที่เปิดอยู่จริง (คนละ `customerId` ต้องได้ลิงก์คนละอัน) และผูกจริง
    ใน request หลังกดบันทึก
- ไม่กระทบ:
  - `app/lib/db.ts` และ `SCHEMA_VERSION` — ไม่มีคอลัมน์/ตารางใหม่
  - `task_links` schema, `TASK_LINK_TARGETS`, ระบบผูกลิงก์ประเภทอื่น
    (equipment / quotation / document) — ปุ่มนี้ผูกได้เฉพาะ "customer" เท่านั้น
    ตามที่ขอ ส่วนลิงก์ประเภทอื่นยังต้องเพิ่มเองในฟอร์มตามปกติถ้าต้องการ
  - `/crm/alerts` และกระดานงานเดิม — behavior เดิมทุกประการ
  - `app/lib/taskStore.ts` และทุก route ใต้ `/api/admin/tasks*` — ไม่แก้แม้แต่
    บรรทัดเดียว เพราะรับ `links[]` ได้อยู่แล้ว
